# Rich Markdown visual contract

Conversation and pending-question owners pass `Markdown.rich: { streaming: boolean }` to the same Markdown component. Omission disables visual/math activation. Generic inspectors and plugin previews retain their existing no-image/no-engine behavior. Active streams retain source; completed messages additionally require a closed, matching code fence. Debouncing is not a completion signal. Math requires closed delimiters. Render/import/parse failures quietly retain source. Question options remain plain text; question images retain independent explicit-click authorization and scope retirement.

The shared AST transform admits only `details`/`summary`, `kbd`, `sup`, `sub`, `mark` and complete native SVG. Arbitrary HTML remains disabled (`skipHtml`); semantic tags copy no attributes except boolean `details.open`. Native disclosures keep keyboard behavior and open state across ordinary updates. Their bodies preserve Markdown and exact code offsets, including CRLF. Matching code delimiters are opaque, including unclosed fences; embedded HTML/SVG code examples never activate. Tables scroll within `.markdown-table-container` (also retaining the existing `.table-container` class). CodeBlock groups Expand and Copy at the right edge in ordinary and visual toolbars.

CodeBlock's existing toolbar owns a native Preview/Raw dropdown, exact underlying fence-body Copy, and ContentDialog expansion. Original body bytes (including CRLF and the newline before the closing fence) are used for source, Copy and inspection. This deliberately corrects only rich fence copying; ordinary code fences keep existing behavior. Original Markdown text is never rewritten. A modal owns a separate renderer instance.

## Admitted data and work budgets

- Native SVG (`svg`/`xml-svg` fences and complete native `<svg>`): UTF-8 <=65,536 bytes, depth <=32 and <=1,024 elements. Both modes use `svg-policy.ts`: browser XML DOMParser, SVG namespace reconstruction, geometry/text/defs/gradient/clip/mask/marker/pattern allowlists, no scripts/events/foreign HTML/links/images/resources/animation/DTD/entities. Only explicitly admitted attributes and presentation properties survive. CSS escapes/comments/at-rules/variables and external URLs are rejected. Local `url(#id)` references must resolve within this exact graphic. IDs, classes, CSS selectors and ARIA references are rewritten per renderer instance, preventing host-style class collisions and cross-graphic reference collisions. Style blocks admit scoped tag/class/ID descendant/child selectors and presentation-only declarations. Unsupported or malformed input retains exact source; no partial-success mutation. Root uses responsive dimensions and inherits current text color unless authored; authored colors are retained. Safe SVG style handling does not enable ordinary HTML styles. Mermaid retains its separate existing generated-output policy and 1 MiB cap.
- Mermaid: graph/flowchart, sequenceDiagram, classDiagram and stateDiagram/-v2 only; UTF-8 source <=12,000 bytes, <=160 lines, <=240 edge/node syntax markers; fixed maxEdges=240 and maxTextSize=12,000. YAML frontmatter is excluded by the anchored diagram-type admission. Mermaid directives/comments (`%%`), HTML opening syntax, links/clicks, image/icon and styling/configuration commands are rejected. This is intentionally conservative: labels containing forbidden command words or advanced syntax may remain source. Ordinary `A --- B` undirected edges are admitted. Fixed strict configuration, HTML labels disabled, and no bindFunctions call. Shared initialization/parse/render is serialized. Each mount/render uses a fresh ID. Detached/stale work cannot install output. Temporary render DOM is removed in finally. Output is capped at 1 MiB and re-parsed as SVG; active/foreign/link/image nodes, event/resource attributes, external CSS URLs/imports and non-local URL references are rejected before insertion.
- ECharts: UTF-8 JSON <=32,768 bytes, depth <=12, <=24,000 visited values, <=16 series, <=4,000 total series points; category arrays <=4,000; <=2 zoom controls; strings <=2,000 UTF-16 code units; finite numeric magnitude <=1e12. Only title text/subtext, legend show/data, tooltip show/trigger, xAxis/yAxis type/name/data/min/max, series name/type/data/stack/smooth and dataZoom type/start/end are accepted. Supported charts: line/bar/scatter/pie. Points are finite numbers/null, numeric pairs, or name/value records. Axis types: category/value. Unknown properties fail closed. Proto keys, URLs, HTML syntax, image surfaces and CSS URL syntax are rejected throughout. Tooltip uses canvas rich text; no HTML formatter/functions/dataset/graphic/resources. Animation and progressive rendering are disabled. Lazy init and update errors retain source. The same mounted container/instance survives invalid input and recovery; ResizeObserver owns resizing. Stable ordinary updates, theme recreation, modal opening/closing and Source/Preview toggling retain legend selection and zoom percentages. The original CodeBlock owns a shared bounded projection (up to 4,080 admitted legend/series/pie-slice names mapped to booleans and up to two finite 0–100 zoom pairs); inline and dialog instances subscribe to the same choices. No complete getOption snapshot, chart data, engine instance or persisted browser state is retained. A fresh CodeBlock owner or changed structural identity (title, legend names, axis types/names, series names/types/stacks, pie-slice names or zoom types) resets choices. Numeric data updates within that identity retain them. Invalid source does not overwrite the last admitted identity; stale renderer events cannot overwrite a newer identity.
- KaTeX: UTF-8 expression <=4,096 bytes; trust=false, strict=error, maxExpand=100, maxSize=10, fresh macros per expression. Resource/HTML/macro-definition commands are refused before engine activation. Numeric-leading single-dollar content, whitespace-delimited content and plain words remain raw to avoid currency/ambiguous prose. Single-dollar math must contain a math operator/control marker. Double-dollar display supports numeric starts. Invalid/unclosed expressions remain raw. Engine/CSS and necessary local math glyph fonts load on first admitted math only; no UI/global webfont policy is introduced.

## Verification

Use existing Playwright infrastructure, with no new test framework:

```sh
npm run build -- --manifest
npm run test:browser -- --config playwright.visuals.config.ts --workers=1
npm run test:browser -- --config playwright.visuals-production.config.ts --workers=1
```

Ports default to 18087/18088 and can be selected through MICROCRAB_VISUAL_TEST_PORT / MICROCRAB_VISUAL_PRODUCTION_PORT. Playwright manages the ephemeral fixture/preview processes. Production verification traverses only static entry imports and asserts zero rich-engine/CSS/font references; separately it records requests from unchanged emitted production files and asserts zero rich-engine/font startup requests. Engine gzip ceilings: Mermaid core 180,000 bytes, ECharts engine 220,000, KaTeX 90,000, math wrapper 12,000. These are per emitted entry chunk, not total transitive first-render costs. Mermaid additionally loads the selected diagram/layout dependencies. Small parser/dispatch code does add initial overhead; no zero-overhead or baseline-delta claim is made.
